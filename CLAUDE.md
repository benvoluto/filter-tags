THis repo is a prototype interface for filters that would work with a table of data in column format, where the data is paginated, can be sorted by any column, can be searched through with a search input, and be filtered by criteria entered that filters on multiple columns, each filter handling a single or multiple criteria as well as search results. 
Please use shad-cn as the basis for the design components and styles (like a chip, table, button, etc.), with the Claymorphism theme available from https://tweakcn.com/.
Please create a table with sample data for 50 rows and 12 columns with pagination controls for 3 pages at bottom.
The interaction should work like this in the default state the table shows all of the columns of data with one column or more in default, sort states with an indicator. At the top of the table, there is a search box and next to that there is a button that says add filters. In addition, if the user hovers over any of the columns, they see a high state for that column, and also controls to change the sort, order or filter by that column. To add a filter, the user can click the “add a filter” button (a popover panel appears under the Add a filter button with a combobox to select/type a column to filter on; when they select a column, the panel expands to show a combo box to select from a list of criteria values in the table data for that column/type their criteria, an “advanced filter” button, and buttons to cancel or confirm filter addition). Or, they can hover over any column header which will show a filter icon-button (when clicked a popover panel appears under that column with a combo box to select from a list of criteria values in the table data for that column or type their criteria, an “advanced filter” button, and buttons to cancel or confirm filter addition. If the user chooses “advanced filter”, a comparator selector is added between the column chosen and a criteria entry area that allows for equals [default], greater than entry, less than entry, is not null, is not entry, if/then, etc). If the user chooses multiple criteria values, they accumulate in the entry as criteria chips, each with an icon-button to remove that chip.
Whichever way a filter is added, a filter chip is then inserted between the search box and “add a filter” button above the table. As the user adds additional filters the filter chips accumulate in that space. If there are more than two filter chips added, a “clear filters” button appears next to the always visible add filters button. 
Each filter chip has a truncated criteria excerpt, a count (if multiple criteria are selected), an edit icon-button (edit appears only when the user hovers over the filter chip), a tooltip (which appears when the user hovers over a filter chip that shows a summary of the full criteria for that filter), and a delete icon-button, and a filter chip should be no wider than 200 pixels. Please allow for some filter criteria to be many (6-9) items.
The search box has a text entry with placeholder “Search or prompt to sort and filter” and a search icon. If a user enters a search criteria value a clear search icon-button appears. If the user has entered some search criteria into the search box and search results are displayed, a “save as filter” button appears in the search box to the right of the clear search icon-button. If the user enters a longer criteria string into the search input, it grows vertically down, overlapping the table. If the user types the names of columns with values to filter on in plain text, the search input parses those values into multiple filter criteria (can defer this feature). If the user adds a search criteria as a filter, they create a filter chip that accumulates along with all the other filter chips in the same spot, and can be edited cleared like other filter chips. 
Please create a project on Vercel and deploy via this repo, using nextjs or whatever you recommend that is most expedient. The table and filters should be adaptable for mobile.
